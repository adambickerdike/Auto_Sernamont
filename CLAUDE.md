# Working on this repository

Instructions for Claude Code. Read before changing anything here.

## What this is

`Auto_Sernamont` is the documentation-first home of the automated Sénarmont
polarimetry system that measures the linear electro-optic response and the
ferroelectric switching of a 10 by 10 electrode array on a BaTiO₃ thin film at
1550 nm. It drives a real bench: three motorised polarisation optics, a
two-axis stage, a 100-channel electrode switching matrix, a source-measure
unit, a function generator, an oscilloscope and a lock-in amplifier.

The lab working copy lives separately at `/mnt/d/Pockels_Setup/Control/`, which
is the `Automated-Pockels` repository. This one is the clean, documented,
public-facing version. They are not the same repository and neither is a
submodule of the other.

## House rules

These were set by the repository owner. They are not stylistic preferences to
be weighed against other concerns.

### 1. No dashes used as punctuation. None.

No em dash, no en dash, no double hyphen in prose, anywhere: documentation,
README, commit messages, figure text, docstrings, code comments. The owner
finds them a tell of machine-written text and asked for every one to be
removed. Roughly 805 were removed by hand; do not reintroduce them.

Use a comma, a colon, a semicolon, a full stop or parentheses instead, and
rewrite the sentence rather than swapping the character. Write ranges as
"1 to 9 Vpp", never with a dash.

Hyphenated compounds are fine and expected: lock-in, null-slope, half-wave,
out-of-plane, second-order. Command-line flags are fine: `--pixels`, `--cli`.
Markdown horizontal rules and table separators are fine.

### 2. Never invent a citation detail.

No invented DOI, volume, issue, article number, page range or author list. The
bibliography at `docs/references.md` omits DOIs by stated policy, because a
mistyped DOI resolves confidently to the wrong paper. If a bibliographic detail
is not certain, leave it out and say nothing rather than guess. Under
specification is deliberate and is explained at the top of that page.

When a citation can be verified from a file the project already holds, verify
it. Reference 61 was confirmed from the supplementary PDF in the lab folder,
including its full author list.

### 3. Figures are computed or measured, never illustrative.

Every figure in `assets/figures/` is generated by a script in `tools/`. The
polarisation states come from the Jones calculus in `tools/_polarisation.py`,
including the compensating quarter-wave-plate angle, which is solved
numerically rather than assumed. The hysteresis figures are built by calling
the production analysis module over real acquired CSVs in `assets/data/`.

Do not add a stock illustration or a hand-drawn curve where a computed one is
possible. Where a drawing is necessarily schematic, such as the phase-diagram
boundaries, say so in the caption and in `assets/README.md`.

### 4. The README is a landing page.

It states what the system is and links out. It is not the documentation. A
long-form README was written and rejected; do not rebuild one. New material
belongs on a page under `docs/` with a link added to the index.

### 5. Report what is true.

Say when a number is a calculation rather than a measurement. Say when data
predates a limit that the documentation now states, as two of the committed
hysteresis runs do, having been taken at plus or minus 50 V before the plus or
minus 40 V ceiling. Say when a conclusion needs a second opinion, as the
reversed peak-angle table in `docs/physics/04-incident-polarisation.md` does.

## Layout

```
pockels/     the measurement package, flat so sibling imports keep working
tests/       23 test files, no hardware needed, all must pass
firmware/    the Arduino switching-matrix sketch
docs/        29 pages, the manual
assets/      schematic, GDS layout, generated figures, curated example data
tools/       figure generation, documentation checks, Windows USB setup
```

`pockels/` is deliberately flat. Every module imports its siblings by bare
name, so do not reorganise it into subpackages without rewriting every import.
`pockels/_bootstrap.py` pins `sys.path[0]` to `pockels/` and the working
directory to the repository root, so run outputs always land in one place.

`tests/_bootstrap.py` does the same job for the tests, and provides
`module_path(name)` because the tests read module source with `ast` rather than
importing it. That is what lets the suite run with no PyVISA, no pythonnet and
no display.

## Before pushing

```bash
python tools/check_docs.py                            # seven checks, see below
python -m unittest discover -s tests -p "test_*.py"   # every test file, no hardware
cd tests && for f in test_*.py; do python "$f"; done  # the per-file form CI uses
```

`tools/check_docs.py` runs seven checks: dashes, links, anchors, citations,
pipes inside table math, whitespace inside inline math delimiters, and `$$`
standing alone on its line. It exits non-zero on failure and is safe to wire
into CI. It knows GitHub's own anchor slug rules, including unicode letters, so
a heading containing "Poincaré" resolves correctly.

After changing a constant that a figure quotes, regenerate the figures:

```bash
cd tools
python fig_polarisation.py        # ellipses and Poincaré sphere
python fig_measurement.py         # Malus, analyser response, harmonics, taxonomy
python fig_material.py            # perovskite, rotation, strain, domains
python fig_system.py              # pixel grid, switch matrix, timing
python fig_measured_hysteresis.py # the two figures built from real data
python fig_brand.py               # banner and logo
```

## Facts that are easy to get wrong

| | |
| --- | --- |
| Signed angular fit | harmonic **2**. The magnitude is four-lobed and gets a separate harmonic 4 fit. Fitting the signed complex response at harmonic 4 destroys the sign reversal, and that was a real bug |
| Lock-in sensitivity | index 16, 200 µV RMS full scale, held **fixed** for a whole map. Index 14 is 50 µV and over-ranged |
| Lock-in time constant | index 14, 500 ms, 12 dB per octave, so settling is 2.0 s |
| DC ceiling | plus or minus 40 V, hard, with 1 mA compliance |
| Drive | 9 Vpp for mapping, 4 Vpp for the hysteresis probe, both at 30 kHz |
| Shift registers | 112 bits: 100 channel relays, 10 group enables at bits 100 to 109, 2 spare. Not "100 used" |
| Detector | Thorlabs PDA30B2, 0.875 A/W at 1550 nm, 10 dB gain, Hi-Z. Do not assert its semiconductor, the repository does not record it |
| Pixel numbering | `pixel = 10*row + col + 1`, row and col 0-based. The GUI draws `display_col = 10 - col` so the map matches the camera |
| HWP grid | 9 points, 22.5 degrees apart in θᵢ, centred on θᵢ 81.8688 degrees lab, which is HWP raw 7.8951 degrees |

## Data

Run folders are created at the repository root and are git-ignored. They are
data, not code, and they do not belong here.

The one exception is `assets/data/`, eight small curated CSVs copied from real
runs with a manifest recording the run and pixel each came from. They exist so
the measured-data figures regenerate from a fresh clone. Do not add more
without a reason, and do not commit a whole run folder.

## Git

Commit messages explain **why**, not just what, and they contain no dashes.
Push to `git@github.com:adambickerdike/Auto_Sernamont.git`.

There is no `gh` CLI and no GitHub API token on this machine. SSH push works;
creating a repository does not, so a new repository has to be made by hand
first.

## Known open item, now checked

`docs/physics/04-incident-polarisation.md` section 8 states the reverse of
what `ORIENTATION_CALIBRATION.md` in the lab repository says: the axial
mechanism peaks at 45 degrees to the field and the shear mechanism along it,
not the other way round. The derivation is on the page and in section 3, and
the reversal is flagged in a note. It affects interpretation of which tensor
element dominates, not any measured number.

The derivation was re-checked in the September 2026 review pass and the table
stands. The check also showed that the shear mechanism survives the limit of
zero static retardance, as a small induced retarder with its axes at plus or
minus 45 degrees to the field, so the Sénarmont response to it is maximal with
the input along or across the field, exactly as the table says. The numerical
tests behind the corrected statements are in
`tests/test_docs_physics_claims.py`. No reviewer is named here because the
owner has not supplied a name.
